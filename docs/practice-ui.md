# 앱·절차 실습 UI

각 필드는 **중톡이와 인사 → `같이 해봐요` 실습 → JRPG 상황 문답 → 서버 채점·해설·보상** 순서로 진행합니다. 실습 단계는 별도의 작업공간에서 열립니다. 중톡이는 옆에서 현재 단계의 확인 사항을 안내하고, 이용자는 앱이나 절차 단말 안의 버튼을 눌러 다음 화면으로 이동합니다.

실습을 끝내면 같은 필드의 하단 JRPG 대화창으로 돌아옵니다. 가상 예약증·탑승권·입국 스탬프를 만들거나 차량을 확인한 것만으로 XP를 지급하지 않습니다. 이후 상황 문제를 제출하고 Django 서버에서 채점한 결과에 따라 완료와 보상을 기록합니다.

## 화면 구성과 공통 동작

- 준비·입국은 절차 단말, 호텔·디디는 모바일 앱을 본뜬 화면을 사용합니다.
- 단계가 바뀌면 기기 안의 스크롤을 맨 위로 이동합니다. 호텔·디디의 이전 단계 버튼은 선택한 값을 유지합니다.
- 실습에서는 검색·날짜 입력·체크박스·라디오 선택의 기본 키보드 동작을 사용합니다. JRPG의 Enter·방향키 단축키로 입력을 가로채지 않습니다.
- 앱·단말을 열어둔 동안 포커스는 실습창 안에 유지합니다. Escape 또는 닫기로 필드에 돌아가며, 실습 종료 버튼은 JRPG 질문으로 이어집니다. 디디의 필드 탑승 동안에는 실습창의 포커스 제한을 풀어 이동·차량 선택을 허용합니다.
- 앱·단말 조작 중에는 캐릭터 이동을 멈춥니다. 디디의 필드 탑승 단계에서는 앱을 잠시 숨기고 이동을 다시 허용합니다. 기존 필드와 실시간 방 연결은 유지합니다.

## 1. 여행 준비 · TRIP WALLET

| 단계 | 이용자가 해볼 일 | 다음 단계 조건 |
|---|---|---|
| 여행 일정 | 출발·귀국 날짜와 ICN → PVG 가상 항공편 선택 | 유효한 날짜, 귀국일이 출발일 다음 날 이후, 예시 항공편 선택 |
| 여행 지갑 | 서류·통신·결제 카드를 열어 준비 항목 점검 | 세 카드의 필수 확인 항목 완료 |
| 탑승권 확인 | 공항·날짜·항공편·좌석이 표시된 교육용 탑승권 읽기 | 최종 확인란 선택 후 상황 문답으로 이동 |

서류 카드는 여권·예약 내역·입국 요건 확인을, 통신 카드는 사용 방식과 오프라인 지도 준비를, 결제 카드는 테스트와 대체 수단 점검을 연습합니다. 실제 가입, 카드 등록, 항공편 예약이나 체크인 요청을 수행하지 않습니다. 탑승권의 `TRAINING`·`DEMO` 표시는 실제 탑승에 사용할 수 없는 예시라는 뜻입니다.

## 2. 입국 절차 · ARRIVAL TRAINING DESK

| 단계 | 이용자가 해볼 일 | 다음 단계 조건 |
|---|---|---|
| 여권 확인 | 화면의 `SAMPLE PASSPORT` 불러오기 | 예시 여권 확인 |
| 카드 작성 | 예시 여권의 이름·국적과 여행 내역을 보고 국적·항공편·방문 목적·숙소 선택 | 예시 여권의 KOREA, 일정의 MU5052·관광·와이탄 가든 호텔과 일치 |
| 내용 검토 | 여권·항공편·숙소 내용을 다시 대조 | 검토 확인란 선택 |
| 심사 연습 | 작성한 카드의 방문 목적과 숙소에 맞게 답변 | 카드와 답변이 일치 |
| 완료 | 교육용 스탬프 확인 | 앞선 확인과 일치 조건을 모두 충족한 뒤 JRPG 문답으로 이동 |

이름과 국적은 예시이며 실제 여권 사진을 업로드하거나 개인 신분정보를 자유 입력하지 않습니다. 카드 내용을 수정하면 검토·심사 답변을 다시 확인합니다. 교육용 스탬프는 실제 입국 허가가 아니며, 이 화면은 공식 신고서 제출 시스템이 아닙니다.

## 3. 호텔 · Trip Practice

| 단계 | 이용자가 해볼 일 | 다음 단계 조건 |
|---|---|---|
| 검색 | 상하이, 체크인·체크아웃 날짜, 성인 1~4명 확인 | 오늘 또는 이후의 체크인, 최소 1박의 유효한 일정 |
| 검색 결과 | 사진·위치·연습 평점·요금이 있는 두 가상 숙소 비교 | 숙소 선택 |
| 객실·예약 조건 | 더블룸·패밀리룸과 무료 취소·환불 불가 요금 비교 | 객실 최대 인원과 일정 확인 |
| 예약 정보 확인 | 고정 가상 여행자 `KIM GILDONG`, 일정·인원·취소 조건·총액 확인 | 조건 확인란 선택 |
| 가상 예약증 | 예약번호·중문 숙소명·예시 주소·예약 조건 확인 | 중톡이와 상황 문답으로 이동 |

가상 숙소의 기본 1박 요금은 ¥520·¥380이며 패밀리룸 추가금과 환불 불가 요금의 1박당 ¥40 차이를 반영합니다. 최종 총액은 선택한 객실·요금의 1박 가격 × 숙박일수로 계산하고, 검색 결과의 최저가와 구분합니다. 금액은 중국위안(CNY)을 사용하는 학습용 숫자이며 실제 가격·청구액이 아닙니다.

더블룸은 최대 2명, 패밀리룸은 최대 4명인 연습 조건을 적용합니다. 환불 불가 조건과 무료 취소 기한을 읽고 선택하며, 확정 화면은 선택 내용의 스냅샷을 사용합니다. 이전 화면으로 돌아가 숙소·객실·조건을 바꿀 수 있습니다. 실명, 여권번호, 연락처나 결제 수단을 입력하지 않습니다.

## 4. 디디 · 차량 호출 앱 연습

| 단계 | 이용자가 해볼 일 | 다음 단계 조건 |
|---|---|---|
| 목적지 찾기 | 한국어·영문·중문으로 예시 장소 검색 | 결과의 이름·지역을 확인하고 선택 |
| 승차 위치 | 가상 공항 지도·목록에서 A·B 승차장 비교 | 이번 안내 표지와 일치하는 A 구역 선택 |
| 차량 선택 | Express·Taxi의 차종과 연습 견적 비교 | 차량 유형 선택 |
| 호출 정보 확인 | 출발지·목적지·차량·견적 재확인 | 가상 호출 버튼 선택 |
| 배정 정보 확인 | 앱에서 배정 번호를 기억하고 필드로 이동 | 개인별 훈련 차량 세 대 진입 |
| 필드에서 차량 찾기 | 캐릭터로 차에 다가가 번호판 직접 대조 | 차량 클릭으로 자동 접근하거나 직접 이동·F 키로 선택 |
| 근접 탑승 | 가까운 차의 탑승 버튼 선택 | 배정 번호가 맞으면 문 열림·출발, 다르면 안내 후 재선택 |
| 앱 완료 내역 | 출발지·목적지·차종·탑승한 번호 확인 | JRPG 상황 문답으로 이동 |

후보 번호는 `沪B·DEMO`, `沪A·DEMO`, `沪A·TRAIN`이며 정답은 호출마다 무작위로 배정합니다. 같은 색의 차량을 사용하므로 앱의 배정 번호와 번호판을 대조해야 합니다. 차량이 대기 중이고 캐릭터가 충분히 가까이 왔을 때만 탑승할 수 있습니다. 다른 차량을 골랐다면 다시 선택하고, 정답 차량의 문 열림·출발 연출이 끝나면 앱 완료 화면으로 돌아옵니다. 취소하거나 필드를 떠난 요청이 뒤늦게 탑승 완료로 이어지지 않도록 타이머와 요청을 정리합니다.

훈련 차량은 이용자별 브라우저 상태이므로 다른 여행자의 배차·탑승을 변경하지 않습니다. 캐릭터가 필드에서 걷는 위치는 기존 소켓으로 다른 여행자에게 공유됩니다. 목적지 후보는 예시 숙소 두 곳과 난징둥루이며 검색은 로컬 목록에서 수행합니다. 실제 지도·GPS·전화번호·디디 계정이나 결제 수단을 사용하지 않습니다. 기사·차량·승차장·번호·견적은 모두 연습 설정이며 실제 호출, 이동 또는 결제를 요청하지 않습니다.

## 구현 경계

[`ScenarioPractice`](../src/components/ScenarioPractice.tsx)는 실습 ID로 모듈을 선택하고 [`PracticeWorkspace`](../src/components/practice/PracticeWorkspace.tsx)에 담습니다. 모듈은 [`PracticeProps`](../src/components/practice/types.ts)의 콜백 계약을 사용합니다.

| 콜백 | 역할 |
|---|---|
| `onGuide(text)` | 중톡이의 단계별 안내 문구 갱신 |
| `track(type, properties)` | 단계·선택·완료의 구조화 이벤트 수집 |
| `onFinish()` | 완료 조건을 확인한 뒤 `MissionDialogue`의 질문 단계로 복귀 |
| `onRideRequested(request)` | 디디 앱을 잠시 숨겨 필드 탑승을 진행하고, 요청·차량이 일치하는 결과 또는 취소를 Promise로 반환 |

준비·입국·호텔의 날짜·완료 조건과 요금 계산은 [`practiceFlow`](../src/lib/practiceFlow.ts)의 순수 함수로 검증합니다. 실습의 화면 상태는 브라우저 메모리에 유지하므로 실습을 닫거나 새로고침하면 초기화됩니다. 완료된 서버의 시나리오 진도·XP는 별도로 유지합니다. 실습의 완료 ref는 같은 실행 중 중복 클릭을 제한하며 서버의 보상 멱등성이나 영속 분석 원장을 대신하지 않습니다.

## 행동데이터

| 이벤트 | 기록 내용 |
|---|---|
| `practice_item_checked` | 준비·예시 여권 등의 항목 ID와 확인 여부 |
| `practice_stage_completed` | 준비·입국 절차의 완료 단계 |
| `practice_step_completed` | 호텔·디디의 완료 단계와 예시 선택 ID |
| `practice_action_completed` | 가상 탑승권·입국 절차·예약·차량 확인 완료 |
| `practice_ui_finished` | 실습을 마치고 JRPG 질문으로 복귀 |

이벤트는 실습 ID와 항목·단계·예시 목적지·숙소·객실·차종, 인원·숙박일수·연습 총액 등 구조화된 값만 사용합니다. 목적지 검색 원문, 입력한 날짜, 실제 이름·여권·전화번호·결제 정보나 채팅 본문을 분석 속성에 담지 않습니다. 브라우저 이벤트 큐는 최선 노력 전송이며, 서버가 채점한 `scenario_completed`·완료 보상과 분리합니다.

## 검증 범위

`npm run test:practice`는 유효한 달력 날짜, 일정·준비 항목의 완료 조건, 입국 카드와 심사 답변의 일치, 객실 인원·숙박 요금 계산과 초기 UI를 검사합니다. `npm run test:taxi`는 후보 차량 구분, 물리 거리·단계·선택·배정·취소 조건과 스폰·NPC에서 세 차량 문까지의 충돌 없는 연속 이동을 검사합니다. `npm run test:render`는 공통 실습창과 모듈 렌더링을 확인합니다. 실제 브라우저의 클릭·포커스·스크롤과 모든 화면 전환을 자동 조작하는 검증은 브라우저 제어 호스트가 없어 수행하지 못했습니다.

# China Passport · 차이나 패스포트

중국 여행 전에 출발 준비, 입국심사, 호텔 예약·체크인, 디디 호출을 연습하는 2D 멀티플레이 여행 서비스입니다. 첫 화면인 **여행 허브에서 분야를 선택하면 각각의 독립 필드로 이동**하고, 해당 필드의 NPC를 통해 체험합니다. **React + TypeScript / Django + Django Channels / SQLite**로 구현했습니다. 이용자는 별도 프로그램 설치 없이 PC·모바일 브라우저로 접속합니다. 아래 설치 절차는 서버 개발·실행을 위한 안내입니다.

참고한 서비스 구성: [PLAYDATA 캠퍼스 메타버스 PRODUCT.md](https://github.com/encore-ai-campus/mlo-01-p3-team2/blob/main/PRODUCT.md). 대상 사용자와 기능·흐름은 [PRODUCT.md](PRODUCT.md), API와 동시성·추상 계약은 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)에 설명했습니다.

## 실행

Node.js 22.12 이상 또는 24, Python 3.12 이상을 사용합니다.

```sh
npm ci
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python server/manage.py migrate
npm run build
npm run server
```

**http://127.0.0.1:8000**에서 화면과 API, WebSocket을 함께 제공합니다. 현재 작업 환경에는 npm·Python 의존성, 마이그레이션과 프런트 빌드가 준비되어 있습니다.

프런트 수정 시 별도 터미널에서 `npm run dev`를 실행하고 **http://127.0.0.1:5173**에 접속합니다. Vite가 `/api`, `/ws`를 8000번 Django 서버로 전달하므로 `npm run server`도 켜 두어야 합니다. 5173번 포트가 사용 중이면 Vite가 선택한 주소를 `ALLOWED_ORIGINS`에 추가합니다.

`.env.example`은 설정 예시이며 자동으로 읽지 않습니다. 필요한 값은 셸 환경으로 내보내세요. 기본 설정 그대로 실행하면 `<프로젝트>/data/passport.db`에 SQLite DB가 생성됩니다.

## 체험

- 첫 화면의 네 입구에서 `여행 준비`, `입국심사`, `호텔`, `디디` 중 하나를 골라 전용 필드에 입장합니다. 허브의 카드는 분야별 입구이며, 체험은 필드 안에서 시작합니다.
- 필드 안에서 W/A/S/D 또는 방향키를 누르고 있으면 부드럽게 걷습니다. 바닥을 클릭하면 해당 지점까지 장애물을 피해 걸어갑니다. 안내 NPC 중톡이 근처에서 F·E·Space로 대화하거나, 중톡이를 눌러 가까이 걸어간 뒤 대화를 시작합니다.
- 첫 대화 후 `같이 해봐요` 단계에서 별도의 앱·절차 실습창을 엽니다. 여행 준비 지갑, 입국 절차 단말, 호텔 예약 앱, 디디 호출 앱에서 화면 안의 버튼으로 과정을 진행합니다. 실습을 마치면 하단 JRPG 대화창으로 돌아와 3개 상황의 답을 골라 제출합니다.
- 모든 답을 맞히면 완료 스탬프와 XP를 받습니다. 첫 완료 보상은 준비 100, 입국 150, 호텔 150, 디디 100 XP입니다. 복습·동시 제출로 보상이 중복되지 않습니다.
- `필드 채팅`으로 같은 필드의 여행자와 대화합니다. 필드마다 접속자와 대화가 분리되며 최근 30개 대화를 복원합니다. 채팅 길이는 300자입니다. 다른 브라우저·시크릿 창을 열면 독립된 여행자가 접속합니다.
- `허브로 돌아가기`로 다른 분야를 선택합니다. `여행 가이드`, `나의 여정`, `나의 여행 여권`에서 연습 내용과 진행 상황을 보고 분야별 필드로 이동합니다.

허브는 `#/hub`, 네 필드는 `#/fields/prepare`, `#/fields/immigration`, `#/fields/hotel`, `#/fields/didi` 경로를 사용합니다. 필드 주소를 직접 열거나 새로고침할 수 있고 브라우저 뒤로·앞으로 가기도 지원합니다. 허브·가이드·여정 화면에서는 WebSocket을 연결하지 않으며, 필드 이동 시 이전 방을 떠나 해당 필드의 방에 새로 접속합니다.

첫 접속에는 임의 닉네임과 기본 여행자 캐릭터가 배정됩니다. 세션 토큰은 브라우저에 저장하고 DB에는 해시만 보관합니다. 같은 브라우저의 여러 탭은 같은 여행자이며, 브라우저 저장소를 지우면 기존 여권에 접근할 수 없습니다. 이동은 클라이언트의 필드별 바닥·장애물 판정과 A* 경로 탐색을 사용합니다. 대각선 이동 속도는 직선과 같고, 대화·입력창 사용·탭 전환 시 이동을 멈춥니다. 서버는 좌표 범위를 검사하며 장애물 판정을 서버에서 재검증하지는 않습니다.

NPC 인사·질의응답·해설·보상은 필드가 보이는 하단 JRPG 대화창에서 진행합니다. 대사가 나오는 중 Enter·Space를 누르면 즉시 표시하고, 다시 누르면 다음 대사로 넘어갑니다. 방향키와 Enter로 답변을 선택하며 Escape로 닫습니다. `같이 해봐요` 단계는 독립된 작업공간으로 전환하며, 중톡이의 안내 옆에서 실제 절차를 본뜬 앱·단말 화면을 조작합니다. 이때 날짜 입력·선택·검색창의 기본 키보드 동작을 유지합니다.

| 실습 | 화면에서 해볼 과정 |
|---|---|
| 여행 준비 | 날짜·가상 항공편 선택 → 서류·통신·결제 카드 점검 → 교육용 탑승권 확인 |
| 입국 절차 | 예시 여권 확인 → 입국 카드 선택 작성 → 검토 → 카드와 일치하는 심사 답변 → 교육용 스탬프 |
| 호텔 | 숙소 검색 → 결과·객실 비교 → 취소 조건 선택 → 예약 정보·총액 검토 → 가상 예약증 |
| 디디 | 목적지·승차장·차종 선택 → 가상 호출 → 필드에서 세 차량의 번호 대조·접근·탑승 → 출발 후 앱 완료 내역 확인 |

디디에서 가상 호출하면 앱을 잠시 숨기고 필드에서 다시 걸을 수 있습니다. 같은 색의 차량 세 대가 들어오며 배정 차량은 호출마다 무작위로 정합니다. 앱의 번호를 기억하고 차를 눌러 가까이 걸어가거나, 직접 이동해 F 키로 선택한 뒤 근접 탑승 버튼을 누릅니다. 다른 차량을 고르면 안내를 받고 다시 선택합니다. 정답 차량의 문 열림·출발 연출 후 앱 완료 내역으로 돌아가 JRPG 질문을 이어갑니다. 훈련 차량은 각 이용자의 브라우저 상태이며 다른 여행자의 배차에 영향을 주지 않습니다.

모든 숙소·요금·차량·여행자 정보는 교육용 설정이며 실제 예약, 결제, 여권 제출이나 외부 서비스 호출은 발생하지 않습니다. 최신 입국 규정이나 가격을 제공하는 서비스가 아닙니다. 각 단계와 참고한 공식 자료는 [실습 UI 설명](docs/practice-ui.md)에 정리했습니다.

## 캐릭터

이용자는 새로 생성한 여행자 스프라이트로 표시합니다. 안내 NPC **중톡이**는 상위 Second Brain 프로젝트의 브랜드 PNG 원본을 그대로 사용합니다. 필드 NPC·대화창·허브에서 같은 캐릭터를 볼 수 있습니다. [자산과 생성 프롬프트](docs/art/README.md)를 참고하세요.

## 다섯 요구사항의 구현

| 요구사항 | 구현 |
|---|---|
| 동시성 | SQLite WAL·IMMEDIATE 트랜잭션, MySQL 행 잠금, 완료·제출·이벤트 고유 제약, 멱등성 키 |
| 채팅·소켓 | Django Channels, 필드별 방의 접속·위치·채팅, 필드 이동 시 연결 전환, 재연결, 입력 검증·전송 주기 제한 |
| DB 교체 | Django ORM + `DATABASE_URL`; SQLite 디렉터리 볼륨, MySQL 연결·볼륨 설정 |
| 행동데이터 | 이동·미션 선택·답안·완료·채팅 전송의 구조화 이벤트, 배치 수집·중복 제거·자기 집계 |
| 확장성 | `TravelerRepository`, `RoomBroker` Protocol 계약과 구현 분리; Redis 채널 레이어 선택 |

행동 이벤트에는 채팅 본문·실제 여권정보·목적지 검색 원문을 담지 않습니다. 앱 실습은 단계·항목·예시 목적지 ID·객실·차종·숙박일수 등 구조화된 선택만 기록하며, 실습 자체를 마쳤다고 XP가 지급되지는 않습니다. 채팅 본문은 대화 복원을 위해 별도 테이블에 저장합니다. 브라우저 이벤트 큐는 메모리 기반으로 탭 강제 종료 시 일부 유실될 수 있고, 완료·보상은 서버의 상황 문제 채점·트랜잭션 기록을 기준으로 합니다.

## Docker와 DB 마운트

SQLite 파일과 Redis 데이터를 영속 볼륨에 저장합니다.

```sh
docker compose up --build
```

같은 주소 **http://127.0.0.1:8000**을 엽니다. MySQL 8.4 및 전용 DB 볼륨으로 시작하려면:

```sh
docker compose -f compose.yaml -f compose.mysql.yaml up --build
```

기존 외부 DB도 연결할 수 있습니다.

```sh
export DATABASE_URL='mysql://passport:password@127.0.0.1:3306/passport'
.venv/bin/python server/manage.py migrate
npm run server
```

접속 정보의 특수 문자는 URL 인코딩합니다. SQLite → MySQL의 연결 변경은 기존 데이터를 복사하지 않습니다. 별도 백업·이관·검증이 필요합니다. 다중 워커는 공유 DB와 `REDIS_URL=redis://...`를 함께 설정합니다. Redis 없이 기본 InMemory 채널 레이어를 쓰면 단일 ASGI 프로세스로 실행해야 합니다.

공개 배포 시 기본 개발 키를 교체하고 호스트·Origin·HTTPS를 설정해야 합니다. 현재 기본 Docker 포트는 로컬 인터페이스로만 노출합니다. Docker·MySQL·Redis 실환경 조합과 대규모 부하는 아직 검증하지 않았습니다.

## 검증

```sh
npm run build
npm run test:render
npm run test:movement
npm run test:practice
npm run test:taxi
npm run avatar:preview
.venv/bin/python server/manage.py check
.venv/bin/python server/manage.py makemigrations --check --dry-run
npm run test:server
```

자동화 테스트는 중복·동시 제출, 보상 원자성, 세션별 데이터 격리, 이벤트 중복 제거, WebSocket 클라이언트의 접속·이동·채팅 및 재접속 기록을 검사합니다. 백엔드 테스트 11개가 통과했으며 네 필드 사이의 채팅·위치·접속자 격리와 세션·XP 유지도 검사합니다.

별도 렌더·경로 검사는 허브 입구와 독립 필드, 직접 진입·잘못된 경로 처리, JRPG 대화창과 4방향 캐릭터를 확인합니다. 이동 검사는 직선·대각선 속도, 프레임 지연 제한, 장애물·경계 충돌, 클릭 경로의 연속 이동, 네 NPC 접근 경로를 확인합니다. 실습 검사는 달력 날짜·준비 항목·입국 카드와 답변의 일치·객실 인원과 요금 계산 등의 진행 조건과 초기 화면을 검사합니다. 택시 검사는 배정·선택·거리·단계·취소 조건과 세 차량 문까지의 충돌 없는 접근 경로를 확인합니다. 이 검사는 실제 브라우저의 전체 버튼 조작·뒤로가기 검증을 대신하지 않습니다. Compose 설정 문법도 검사했습니다.

이 작업 환경에서는 브라우저 제어 호스트가 제공되지 않아 실제 브라우저 화면 검증을 수행하지 못했습니다. Django 실행 시 포트 바인딩도 환경 제한으로 차단되어 API·소켓은 Django 테스트 서버와 Channels Communicator로 검증했습니다. 프런트 개발 서버의 HTTP 응답과 프로덕션 빌드는 확인했습니다.

## 구조

```text
src/                    React 화면, API·소켓 연결, 행동 이벤트 큐
  components/           허브·분야별 필드와 체험 화면
    practice/           준비·입국·호텔·디디 실습 앱과 공통 작업공간
  lib/                  필드·경로 계약, 타입·HTTP 클라이언트·월드 훅
server/
  config/               Django 설정·ASGI·URL 라우팅
  world/                계약, 저장소, 모델, API, 소켓, 체험, 테스트
    migrations/         버전 관리 DB 스키마
scripts/                Docker 진입점
docs/                   설계 설명
data/                   SQLite DB (Git 제외)
```
